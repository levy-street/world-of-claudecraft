# Участие в разработке World of ClaudeCraft

Прежде всего спасибо, что вы здесь. World of ClaudeCraft создаётся сообществом
людей, которые любят классические MMO, и каждый вклад, большой или маленький,
делает игру лучше. Исправить опечатку, перевести игру, сообщить об ошибке,
построить целое новое подземелье: всё это важно, и мы рады вам.

Это руководство поможет вам всё настроить и сделать первый вклад лёгким и
приятным. Быть экспертом не обязательно. Если что-то непонятно, спросите в
[Discord](https://discord.com/invite/worldofclaudecraft), и кто-нибудь с радостью поможет.

Участвуя, вы соглашаетесь соблюдать наш [Кодекс поведения](../../CODE_OF_CONDUCT.md).

## Как можно помочь

Здесь найдётся дело для каждого:

- **Код.** Исправьте ошибку, добавьте возможность или ускорьте работу. Задачи с
  метками [`good first issue`](https://github.com/levy-street/world-of-claudecraft/labels/good%20first%20issue)
  и [`help wanted`](https://github.com/levy-street/world-of-claudecraft/labels/help%20wanted)
  хорошо подходят для начала.
- **Переводы.** Помогите игрокам по всему миру, улучшив или дополнив какой-нибудь
  язык. Смотрите раздел [Перевод игры](#translating-the-game) ниже. Это один из
  самых простых и при этом заметных способов начать.
- **Сообщения об ошибках и идеи для новых возможностей.** Откройте [задачу](https://github.com/levy-street/world-of-claudecraft/issues/new/choose).
  Понятное описание ошибки уже само по себе настоящий вклад.
- **Документация.** Руководства вроде этого, README и проектные документы в
  `docs/` всегда можно сделать лучше.
- **Тестирование и отзывы.** Играйте, рассказывайте нам, что ощущается не так, и
  делитесь идеями в Discord.

## С чего начать

Вам понадобятся [Node.js 26](https://nodejs.org/) и npm — те же версии, что
используют CI и продакшен-образ. Более старые мажорные версии не тестируются. Для
мультиплеерного сервера также пригодится [Docker](https://www.docker.com/), чтобы
запускать Postgres.

```bash
# 1. Сделайте форк репозитория на GitHub, затем клонируйте свой форк
git clone https://github.com/<your-username>/world-of-claudecraft.git
cd world-of-claudecraft

# 2. Установите зависимости
npm ci

# 3. Укажите git на хуки репозитория (один раз на клон)
git config core.hooksPath .githooks

# 4. Запустите офлайн-клиент (сервер и база данных не нужны)
npm run dev          # откройте напечатанный URL (обычно http://localhost:5173)
```

Этого достаточно, чтобы играть в офлайн-мире и работать над большинством задач.
Чтобы запустить полный онлайн-стек, сначала нужен пароль базы данных в вашем
окружении:

```bash
cp .env.example .env
# задайте POSTGRES_PASSWORD и укажите в DATABASE_URL тот же пароль
npm run db:up        # запустить Postgres 16 в Docker (dev-БД на порту 5433)
npm run server       # собрать и запустить авторитетный игровой сервер на :8787
npm run dev          # в другом терминале; клиент проксирует запросы на сервер
```

Если вы планируете запускать полный набор проверок, описанный ниже, один раз
установите браузер, которым он управляет: `npx playwright install chromium`.

В [README](README.ru_RU.md) есть полное руководство по хостингу, разработке и игре, а
файлы `CLAUDE.md` по всему репозиторию описывают соглашения для каждой области.

### Инструментарий TypeScript

Проверка типов выполняется на TypeScript 7, нативном компиляторе: `npx tsc --noEmit`
работает ровно так же, как раньше, а полная проверка репозитория теперь занимает
несколько секунд вместо десятков секунд. Установка использует официальный двойной
алиас: пакет `typescript` разрешается в JS API TypeScript 6 (через обёртку
`@typescript/typescript6`), потому что `svelte-check` по-прежнему использует этот
API, а `@typescript/native` предоставляет бинарник `tsc`. Что стоит знать:

- **Редакторы.** VS Code нужно расширение "TypeScript 7" из маркетплейса
  (`TypeScriptTeam.native-preview`) для поддержки нативного языкового сервиса, пока
  не выйдет встроенная поддержка; оно переключается настройкой
  `js/ts.experimental.useTsgo`, а его команда "Disable TypeScript 7 Language Server"
  — санкционированный откат на tsserver из TypeScript 6. IDE от JetBrains
  автоматически находят нативный сервер только под именем пакета
  `@typescript/native-preview`, поэтому они не подхватят его из алиаса
  `@typescript/native`, который использует этот репозиторий; их встроенная
  поддержка TypeScript 6 работает нормально.
- **Полезные флаги tsc.** `--checkers N` задаёт число параллельных воркеров
  проверки типов (по умолчанию 4; результат одинаков при любом числе): уменьшите
  его, чтобы ограничить память на стеснённом раннере, увеличьте на машине со
  множеством ядер и в обоих случаях измеряйте, так как больше не всегда быстрее.
  `--singleThreaded` отключает весь параллелизм. Разовая проверка одного файла
  (`npx tsc somefile.ts`) выдаёт ошибку, если в каталоге есть `tsconfig.json`;
  передайте `--ignoreConfig` для прежнего поведения.
- **Lock-файл.** Пересоздавайте `package-lock.json` только командой
  `npx npm@10 install --package-lock-only`: файл использует семантику npm 10, а
  более новые мажорные версии npm (включая npm 11, который поставляется с Node 26
  в CI) молча выбрасывают вложенные записи опциональных peer-зависимостей
  `svelte-check`, что рассинхронизирует `npm ci` в CI. Обычный `npm ci` безопасен
  на любой мажорной версии npm. После пересоздания убедитесь, что
  `npm ci --dry-run` синхронен и под npm 10, и под npm вашей рабочей машины.
- **Когда к этому вернуться.** Свернуть двойной алиас обратно в одну зависимость
  `typescript` можно, когда выполнятся ОБА условия: вышел стабильный JS API
  TypeScript 7.1 (TypeScript 7.0 не поставляет JS API вовсе; замена отслеживается
  в microsoft/typescript-go, задача 2824) и закрыта задача 3063 в
  sveltejs/language-tools вместе с релизом `svelte-check`, который его принимает.
  Экспериментальные режимы `--tsgo` в svelte-check не снимают требование к JS API
  TypeScript 6, а его незавершённая загрузка TypeScript 7 (PR 3073 в
  language-tools) читает тот же алиас `@typescript/native`, который уже
  используется здесь, так что переименование не понадобится.

## Как вносить изменения

1. **Начинайте с самой свежей релизной ветки, а не с `main`.** Активная работа
   интегрируется в ветке `release/vX.Y.Z`; `main` отстаёт от неё и не является
   базой для вкладов. Найдите самую новую и ответвитесь от неё:

   ```bash
   git fetch origin
   git branch -r --list 'origin/release/*' | sort -V | tail -1   # the newest release branch
   git switch -c feature/<short-slug> origin/release/vX.Y.Z
   ```

   Всегда выполняйте эту проверку, а не копируйте номер версии из этого
   руководства: релизные ветки сменяются часто, и самая новая меняется с каждым
   релизом. Ветки называются `feature/<short-slug>` или `fix/<short-slug>`.
2. **Делайте сфокусированные коммиты.** Небольшие самодостаточные изменения
   проще проверять и сливать, чем крупные.
3. **Добавьте или обновите тесты** для любого поведения, которое вы меняете в
   `src/sim/` или `server/`.
4. **Сохраняйте видимый игрокам текст переводимым.** Смотрите разделы
   [Локализация](#localization) и [Перевод игры](#translating-the-game).

### О чём стоит помнить

Это несущие правила кодовой базы. Полные подробности живут в корневом
[`CLAUDE.md`](../../CLAUDE.md), но если коротко:

- **Ядро симуляции (`src/sim/`) это источник истины**, и оно остаётся чистым,
  без импортов DOM, браузера или Three.js, чтобы один и тот же код работал офлайн,
  на сервере и в headless-среде RL.
- **Симуляция детерминирована.** Она работает с фиксированным тиком 20 Hz, и вся
  случайность проходит через `Rng`, а не через `Math.random`, `Date.now` или
  `performance.now` в логике симуляции. Одно и то же зерно всегда даёт один и тот
  же мир.
- **Игровая математика следует формулам классических MMO** (ярость, таблицы
  попаданий, броня, кривые опыта). Пожалуйста, не придумывайте балансные числа.
  Вместо этого ссылайтесь на формулу.
- **Новая логика появляется как отдельный небольшой протестированный модуль за
  существующим швом**, а не дописывается в один из больших координирующих файлов.
  Данные, которые читают рендерер или HUD, проходят через интерфейс `IWorld`
  (`src/world_api/`) и реализуются и в офлайн-, и в онлайн-мире; новая система
  симуляции живёт за `SimContext`; новая REST-точка — это модуль маршрута, каркас
  которого можно создать командой `npm run new:endpoint`.
- **Не редактируйте сгенерированные файлы вручную**, такие как `*.generated.ts`.
  Пересоздавайте их через сборку.
- **Стиль текста в проекте: никаких длинных и коротких тире и эмодзи** нигде — ни в
  коде, ни в комментариях, ни в документации, ни в сообщениях коммитов, ни в тексте
  PR, ни в тексте для игроков. Используйте запятые, двоеточия, скобки или "to" для
  диапазонов. Проверка перед push сканирует ваш diff и блокирует отправку при
  совпадении.
- **Никогда не коммитьте секреты** или файл `.env` и никогда не включайте
  `ALLOW_DEV_COMMANDS` в продакшен-пути, так как это открывает читы.

### Стиль кода

Форматирование обеспечивает [Biome](https://biomejs.dev/), настроенный в
`biome.json`: отступ в 2 пробела, строки по 100 колонок, одинарные кавычки,
завершающие запятые. Форматируйте только те файлы, которых вы касались
(`npx @biomejs/biome check --write <your-file.ts>`), и проверяйте их командой
`npm run ci:changed`. CI проверяет только изменённые файлы, поэтому, пожалуйста, не
переформатируйте остальное дерево: прогон по всему репозиторию поднимает давний
долг, исправлять который не ваша задача.

## Прежде чем открыть pull request

Запустите набор проверок репозитория локально. Это тот же контракт, что выполняет CI:

```bash
npm run gate
```

Во время работы запускайте отдельный набор (`npx vitest run tests/sim.test.ts`) и
`npm run ci:changed` для форматирования; `npm test` запускает всё, а карта наборов
лежит в `tests/CLAUDE.md`. Полный `npm run gate` покрывает свежесть сгенерированных
артефактов, сканирование на вредоносный код, форматирование изменённых файлов,
проверку соответствия звуковых эффектов, весь набор тестов, регрессионный прогон в
настоящем браузере, строгую проверку типов и сборки клиента, сервера и headless.
Многоуровневые проверки, начиная с базового уровня перед push, описаны в
[`docs/qa-gate.md`](../qa-gate.md).

Затем протестируйте изменение и на десктопе, и на мобильном, включая экран
размером с телефон в портретной и альбомной ориентации, если оно затрагивает
что-либо, что видят игроки. Области нажатия должны оставаться не меньше 40x40px, а
поля ввода форм с шрифтом не меньше 16px. Стандарты интерфейса описаны в
[`src/ui/CLAUDE.md`](../../src/ui/CLAUDE.md).

## Открытие pull request

Отправьте свою ветку и откройте PR **против той же самой свежей ветки
`release/vX.Y.Z`, с которой вы начинали. Никогда не выбирайте целью `main`** — это
ветка релизной интеграции, а не база для вкладов. GitHub часто заранее подставляет
`main`, поэтому смените базовую ветку перед отправкой.
[Шаблон pull request](../../.github/PULL_REQUEST_TEMPLATE.md) проведёт вас по короткому
списку проверок. Пожалуйста, заполните его:

- Опишите, **что** изменилось и **почему**.
- Свяжите PR с соответствующей задачей (например, "Closes #123").
- Добавьте **скриншоты или короткое видео для изменений интерфейса**, на десктопе
  и мобильном.
- Подтвердите, что `npm run gate` проходит и что новые строки для игроков следуют
  описанной ниже политике "сначала английский" для участников.

В вашем PR CI прогоняет форматирование и линтинг по изменённым файлам, полный набор
тестов на четырёх параллельных шардах, регрессионный прогон в браузере, а также
проверку типов и сборки клиента, сервера и headless. Это совпадает с тем, что
`npm run gate` запускает локально, поэтому зелёный локальный прогон хорошо
предсказывает зелёный PR.

Зелёный прогон CI и полностью заполненный список проверок это то, на что мы
смотрим перед слиянием. Сопровождающий может предложить правки. Это нормальная
совместная часть процесса, а не отказ. Мы стремимся быть доброжелательными и
конструктивными при ревью и просим того же от вас.

> Сообщения коммитов и заголовки PR следуют [Conventional Commits](https://www.conventionalcommits.org/)
> с указанием области (`feat(talents): ...`, `fix(net): ...`). Каждый коммит также
> несёт тело: после пустой строки от одного до четырёх простых предложений о том,
> что изменилось и почему, с переносом около 72 колонок. Одного заголовка
> недостаточно.

## Локализация

World of ClaudeCraft выходит на множестве языков. Каждая видимая игроку строка
должна быть ключом перевода, при этом участники, добавляющие возможности, обычно
добавляют только английский исходник.

- Весь текст, обращённый к пользователю, это ключ `t()`. Добавляйте новый английский
  текст в соответствующий модуль по доменам в
  [`src/ui/i18n.catalog/`](../../src/ui/i18n.catalog/) (новые элементы HUD идут в
  `hud_chrome.ts`), затем выводите его через `t('dotted.key', values)`. Только
  английский — это ровно то, что нужно для PR с новой возможностью: остальные локали
  сопровождающий заполняет к релизу, поэтому вы не редактируете оверлеи
  `src/ui/i18n.locales/` и никогда не оставляете там английскую заглушку или
  `// TODO`. Исключение M16 — новое многословное английское значение, которому нужны
  также пять заполнений для нелатинских языков, описанных в
  [`src/ui/CLAUDE.md`](../../src/ui/CLAUDE.md).
- Числа, деньги, даты, единицы измерения и проценты проходят через форматтеры
  (`formatNumber`, `formatMoney`, `formatDateTime`, `Intl`), а не собираются из
  строк вручную.
- Текст, обращённый к игроку, который выдаётся из `src/sim/` или `server/` (а они
  остаются нейтральными к языку), должен повторно локализоваться на границе
  клиента в том же изменении. Это обеспечивает контрольный тест
  `npx vitest run tests/localization_fixes.test.ts`.
- После добавления или изменения любой строки запустите `npm run i18n:gen` и
  закоммитьте пересозданные бандлы в том же изменении. И локальные проверки, и CI
  сравнивают закоммиченные артефакты со свежей генерацией, поэтому устаревший бандл
  ломает сборку.

Итак, добавляйте свои строки на английском и открывайте PR; переводить их самому не
нужно. Если вы хотите помочь с переводами, смотрите следующий раздел.

## Перевод игры

Хотите улучшить язык или помочь принести игру на новый? Для этого не нужно писать
игровой код:

1. Большая часть переводов для игроков живёт в файлах оверлеев по языкам в
   [`src/ui/i18n.locales/`](../../src/ui/i18n.locales/) (по одному на локаль), которые
   повторяют английские ключи из
   [`src/ui/i18n.catalog/`](../../src/ui/i18n.catalog/). Текст, выдаваемый симуляцией
   и сервером, переводится в `src/ui/sim_i18n.ts` и `src/ui/server_i18n.ts`, тексты
   талантов — в модулях `talent_i18n`, а у панели администратора есть свой набор в
   `src/admin/i18n.locales/`.
2. Улучшите существующие переводы или дополните те, что звучат неуклюже.
3. Запустите `npm run i18n:gen`, закоммитьте пересозданные бандлы вместе с правкой
   оверлея, затем запустите наборы тестов локализации
   (`npx vitest run tests/i18n_completeness.test.ts tests/localization_coverage.test.ts`)
   и откройте PR. Одна лишь проверка типов не скажет вам, что ключ пропущен,
   поскольку оверлеи намеренно разрежены.

Чтобы предложить совершенно новую локаль или обсудить тон и терминологию, начните
обсуждение в [Discord](https://discord.com/invite/worldofclaudecraft), и мы поможем всё подключить.
Носителям языка и свободно говорящим мы рады особенно. Хорошие переводы делают
игру родной для игроков повсюду.

Пожалуйста, используйте [шаблоны задач](https://github.com/levy-street/world-of-claudecraft/issues/new/choose):

- **Сообщение об ошибке.** Сначала поищите среди [существующих задач](https://github.com/levy-street/world-of-claudecraft/issues),
  чтобы избежать дубликатов, затем приведите шаги для воспроизведения, что вы
  ожидали, что произошло, и опишите своё окружение (офлайн или онлайн, браузер,
  десктоп или мобильный).
- **Запрос новой возможности.** Опишите проблему, которую вы пытаетесь решить, а
  не только решение. Контекст помогает нам спроектировать правильную вещь.
- **Уязвимости безопасности.** Пожалуйста, не открывайте публичную задачу.
  Сообщайте о них приватно, следуя [SECURITY.md](../../SECURITY.md), и мы вместе с
  вами поработаем над исправлением и раскрытием.

## Лицензия

Внося код, вы соглашаетесь, что ваши вклады в код будут лицензированы по
[лицензии MIT](../../LICENSE) проекта, той же лицензии, что покрывает весь проект.

Лицензия MIT означает ровно то, что в ней написано: любой может использовать,
изменять и распространять код, коммерчески или нет. Наши
[Условия использования](https://worldofclaudecraft.com/terms) регулируют игру,
которую мы размещаем на worldofclaudecraft.com (учётные записи, поведение,
виртуальные предметы), и не ограничивают прав, которые лицензия MIT даёт вам или
кому-либо ещё в отношении этого кода. Названия и брендинг "World of ClaudeCraft" и
"Levy Street" лицензией MIT не покрываются.

Исключение составляют оригинальные творческие материалы (звукозаписи, музыка,
графика и подобные авторские работы). Если вы вносите созданный вами оригинальный
материал, вы можете вместо этого сохранить авторские права и передать его по
лицензии на ваш выбор (например, CC BY-NC 4.0) при условии, что:

- лицензия, пути к покрываемым ею файлам и указание авторства записаны в таблице
  лицензий в [CREDITS.md](../../CREDITS.md) в рамках того же pull request, и
- она включает как минимум бессрочное безвозмездное разрешение для Levy Street
  использовать эти материалы коммерчески в World of ClaudeCraft, включая
  официальные релизы и внутриигровой магазин.

Для материалов, перечисленных в таблице CREDITS.md, записанная там лицензия имеет
приоритет над MIT-лицензией проекта по умолчанию.

**Медиаматериалы без записи в CREDITS.md не лицензированы по MIT.** Реестр всё ещё
заполняется, поэтому отсутствие записи означает, что условия не зафиксированы, а не
что материал можно свободно брать. Это сделано намеренно: так незарегистрированный
вклад не раздаётся по умолчанию. С кодом всё наоборот, и всё, что не выделено
отдельно в CREDITS.md, распространяется по MIT.

Именно поэтому запись в реестре — не формальная бумажка. Если вы внесёте материал
без строки в CREDITS.md, никто дальше по цепочке не сможет его использовать, а у нас
не останется свидетельства того, что вы нам передали. Заполняйте честно и колонку
**Redistribution**. Именно она говорит тому, кто форкает этот проект, вправе ли он
передавать ваш материал дальше, и некоторые строки помечены "No, permission
required" ровно потому, что нет.
