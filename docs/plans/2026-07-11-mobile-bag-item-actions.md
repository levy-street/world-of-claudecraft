## Global constraints

- Package manager and runtime: npm, TypeScript ESM, Node runtime from the workspace.
- Fast test command: `npx vitest run <targeted-test-files>`.
- Final test command: `npm test` plus `npm run build` and changed-file Biome checks.
- No new runtime dependencies.
- No DOM, browser, Three.js, or localization runtime imports in pure view/core modules.
- All new player-visible strings use English catalog keys through `t()`.
- Keep every mobile action target at least 40 by 40 pixels with keyboard and forced-colors support.
- Do not grow `hud.ts` with a new menu implementation; keep it as callback wiring only.
- Preserve unrelated dirty-worktree changes and do not hand-edit generated i18n files.
- Every production task follows RED, GREEN, REFACTOR.

## Tasks

### T1: Derive item-specific mobile actions

- **Files:** create `src/ui/bag_item_actions_view.ts`, create `tests/bag_item_actions_view.test.ts`, modify `tests/architecture.test.ts`.
- **Changes:** Define stable menu action ids and a pure resolver for normal mode versus transactional mode, item kind, use metadata, discard protection, and Consumables eligibility.
- **Tests:** Cover gear, bag, all four Consumables kinds, usable tools, quest/junk, every transactional mode, and Destroy as a secondary action that is absent for protected items.
- **Interfaces:** Consumes `BagItemInfo`, `BagMode`, and existing discard rules. Produces `MobileBagItemAction`, `MobileBagItemActionsView`, and the resolver consumed by T5.
- **Depends on:** None.
- **Estimated time:** 5 minutes.

### T2: Build and validate scoped Consumables preferences

- **Files:** create `src/ui/consumable_bar_preferences_core.ts`, create `tests/consumable_bar_preferences_core.test.ts`, modify `tests/architecture.test.ts`.
- **Changes:** Add the versioned six-slot `(string | null)[]` shape, storage-key builder, injected-storage load/save, item-kind validation, assign/move/toggle-remove, and reset operations. The first assignment accepts the current six-slot automatic layout from the caller as its seed; this core never recreates automatic ordering. A failed save keeps the updated in-memory layout usable for the current session.
- **Tests:** Cover online/offline scope isolation, corrupt storage, invalid ids, duplicates, move semantics, current-slot removal, reset, caller-supplied automatic seeding, and storage exceptions while proving the updated in-memory layout remains usable after a failed save.
- **Interfaces:** Consumes a storage-like adapter, character scope, item lookup, and caller-supplied automatic seed on first mutation. Produces `ConsumableBarPreferences` operations consumed by T5 and T7.
- **Depends on:** None.
- **Estimated time:** 5 minutes.

### T3: Resolve automatic and custom quick-bar layouts

- **Tests:** Pin automatic parity, exact custom slot order, empty slots, invalid ids, persistent zero-count assignments, and automatic usability restoration after reacquisition.
