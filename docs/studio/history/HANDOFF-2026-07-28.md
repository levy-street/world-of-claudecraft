2. **The PvP battleground work**: the Ravenrift editor mode, the Thornhollow

stop here and talk to SPACEY before building on it.

## What is new since the last `main` snapshot

### The battleground work (this is the part you want)

**Ravenrift editor mode**, in `src/editor/battleground/`. The shipped
battleground (`src/sim/battleground_layout.ts`) is code-defined geometry, and
until now the only way to move a wall in it was to hand-edit constants. The
editor now loads that layout into the live 3D viewport, on top of the real field
the renderer builds from the same data, so what you see is what the sim collides
against. Entering swaps the live layout for a draft; leaving restores the shipped
set. Three exits: **Save** (draft kept locally, survives a reload), **Export**
(changed consts written back into the source file via a dev-server endpoint),
**Download** (the same literals as a file, when there is no dev server). Open it
from the Ravenrift button on the tool rail.

Decision logic is in pure cores (`bg_draft_core`, `bg_layout_writer_core`,
`bg_validate_core`), so `battleground_mode.ts` stays a thin DOM/three glue layer
and the logic is unit-testable without a browser.

**Thornhollow**, in `src/editor/shipped_thornhollow.ts`. A new capture-the-flag
map, and the opposite construction to Ravenrift: every wall, tree, rune pad and
flag stand is an **ordinary placement in a CustomMap**, so the whole editor
toolset applies to it. Open, Shipped, Thornhollow, drag anything, save it as your
own. 600+ placements. The shape is the classic two-keep flag race: mirrored keeps
at the ends of a wooded ravine, two flank ridges for the high road, a Fightpit
sunk into the middle. Point symmetric by construction (`(x, z) -> (-x, -z)`), so
neither side has an advantage.

The keeps are **two storeys**. Walkable ground in this engine is a heightfield,
so upper floors are built from `collider/plane` volumes, the only thing that
raises walkable ground. That gets you the rampart over the curtain wall, the
stairs up to it, and the flag podium. Read the "Two storeys" note over
`keepRampart()` before you author another one; there are three non-obvious traps
(decks over doorways, placements seating on decks, rails sealing corners).

**Authored-map objectives runtime**, in `src/sim/map_objectives.ts`,
`src/sim/social/map_objectives_run.ts` and `src/sim/social/map_objective_bots.ts`.
This is the one that matters most. Ravenrift has had a complete CTF simulation
for a long time (pickup, carry, drop on death, own-team return, timed
auto-return, the own-flag-home capture gate, scoring) but **none of it could ever
run on a map somebody made**, because every anchor it reads is a module constant
in `battleground_layout.ts` and the whole mode lives in a fixed instance band. A
maker who placed a flag got a banner model and an inert tag.

Now a placement can carry a `regionRole` (`flag0`/`flag1`, `spawn0`/`spawn1`,
`banner`, `graveyard`, `speedRune`, `powerRune`), the map projects those into a
`MapObjectives` record on `WorldContent`, and the driver runs the same rules on
the map's own coordinates. Press the flag key next to your own authored flag and
you pick it up. Practice bots (3 a side) contest it, so walking your own map
tells you whether the lanes actually work.

What it deliberately is **not**: matchmaking, ranked teams, Elo, honor, the
ladder, wave respawns, the graveyard rite. Those are Ravenrift's, tied to its
queue and its instance band. This is a **rehearsal**: one local side, bots on the
other, objective rules faithful. Fully deterministic, with no rng anywhere. Rune
recharges and the flag return clock are tick math; bot decisions are pure
functions of position.

Gating is strict. The driver returns null unless the active content is an
authored map carrying a playable objective record. The built-in world can never
enter this code, and neither can a map that tagged nothing.

**Region round trip**, in `src/editor/regions/region_export_core.ts` and
`src/sim/regions/`. A shipped region can be opened as an editable map and
exported back as production content. This is the path to prod, covered below.

**Collision honesty**, in `src/sim/mesh_prisms.ts`. Collision Master meshes used
to be re-expressed as one yawed rectangle per Y band, which put **10.6% of
collider volume outside the drawn shape** measured over the shipped override
table (61% on the worst rock): an invisible wall short of the thing you modelled.
Bands are now extruded convex prisms chosen adaptively, so a straight-sided
volume stays one prism and a taper spends bands where the shape actually changes.

**Dungeon kit scale**, in `src/sim/dungeon_kit_dims.ts`. The kit is drawn under
two different scale conventions: module scale (the renderer instances the GLB
as-is, so a large floor tile is 4yd) and placement scale (a catalogue asset is
normalized so its largest dimension is 2.2yd). Copying one onto the other shrank
a 4yd wall to 2.2yd while leaving it on a 4yd grid, which is the gapped floors
and undersized walls a region map used to show. Both directions of the round trip
now convert here.

## Getting the battleground into prod

Two different mechanisms, because the two maps are built differently.

**Ravenrift is a region.** Open, Shipped, Ravenrift, edit it as an ordinary map,
then **Workspace, Export to production**. That writes
`src/sim/regions/ravenrift.authored.generated.ts` through a dev-only endpoint
(`/__region_map/save`), and the generated module is what the game ships. Commit
the generated file like any other source.

The split is the whole idea. **Tagged** placements (the `regionRole` anchors) go
back into the region's record, because mode logic, the minimap and the graveyard
code read positions rather than models. **Untagged** placements, meaning kit
modules, collider volumes, and all the walls and cover, ship as ordinary
placements that draw themselves and block with their own collision. So there is
exactly one thing to move when you want a wall somewhere else.

Headless equivalent, byte-identical because it shares the same pure core:

```bash
node scripts/gen_region_map.mjs path/to/ravenrift.wocmap.json
```

`--check` writes nothing and exits non-zero when the module on disk is stale,
which is what you want in a CI gate.

**Thornhollow is not a region.** It is a normal shipped map (`SHIPPED_MAPS`,
group `Battleground`) and it ships as the TypeScript module that builds it.
Editing it means editing `shipped_thornhollow.ts`, or opening it, saving it as a
custom map, and shipping that.

Before either goes live, run the suites that cover it:

```bash
npx vitest run tests/editor_thornhollow.test.ts tests/editor_thornhollow_collision.test.ts tests/editor_thornhollow_keep.test.ts tests/map_objectives.test.ts tests/mesh_prisms.test.ts tests/authored_map_world_leaks.test.ts tests/authored_prism_collision.test.ts tests/region_map_roundtrip.test.ts tests/region_ravenrift_map.test.ts tests/editor_region_kit_scale.test.ts
```

## Things that will bite you

- **`tests/authored_map_world_leaks.test.ts` exists for a reason.** Anything in
  the game that lives at fixed world coordinates leaks into an authored map: the
  Sowfield's boards and its bot match, Eastbrook's town, jail and stations.
  Anything that reads active content self-gates and is fine. If you add content,
  that test is the gate.
- **The pathfinder is Y-blind.** Bots route in XZ. On a two-storey keep they
  will happily path through a floor if the geometry allows it. The bot steering
  caps step-up at 0.5yd to match the player's own climb, which is what keeps them
  on ramps and stairs.
- **`.githooks/pre-push` is not installed** in this clone (`core.hooksPath` is
  unset). If you want the QA floor (typecheck, guard tests, scoped lint, copy
  rules) run `git config core.hooksPath .githooks`. Be aware that
  `tests/architecture.test.ts` is already red for pre-existing reasons, so the
  hook will block every push until those fork-only modules get registered.
- **Generated files are committed, not built on clone:**
  `manifest.generated.ts`, `asset_collision_overrides.generated.ts`,
  `dungeon_kit_dims.generated.ts`, `ravenrift.authored.generated.ts`. If you
  regenerate one, commit it. The media manifest in particular has a history of
  being clobbered from upstream and silently dropping 349 Medieval Village
  entries; regenerate it with `node scripts/build_media_manifest.mjs generate`.
