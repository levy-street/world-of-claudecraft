**Long continuous loop + the real result (2026-07-01):** `bench/run.mjs --minutes N` authors against a wall-clock budget (not a fixed `--iters`), rewriting its summary + growing its trajectory after every edit and nudging a different strategy when stuck; `bench/loop.mjs` scores the floors once then runs codex + a local qwen model authoring in PARALLEL for the whole budget so the dashboard shows continuous progress. **Key bug found + fixed:** the first sweeps "sucked" (models barely beat baseline) NOT because of model quality but because the harness `maxTokens` default was 400 (right for the live planner's tiny JSON intent, wrong for policy authoring), which TRUNCATED authored policies mid-statement -- qwen2.5-coder:3b failed to compile ~92% of its edits (133/144). Fix, band-aid first (d3e165d): `AGENT_MAX_TOKENS` env override + truncation-repair in `compilePolicy`. Then the PROPER source-level fix (commit 5a68460, after the user said "fix the harness bug"): (1) `complete()` no longer silently returns truncated output -- it inspects `finish_reason==='length'` / `stop_reason==='max_tokens'` and retries once with a doubled cap up to `maxTokensCeil`; (2) added env-configurable `AGENT_FREQ_PENALTY`/`AGENT_PRESENCE_PENALTY` (loop.mjs sets them for qwen) to stop the degenerate repeated-clause generation that was the ROOT cause of the truncation; (3) `compilePolicy` now handles EVERY wrapper form a model returns (bare body, `function policy(){}`, anon function, method-shorthand `policy(view,mem){}`, arrow block, arrow expr, fenced) -- the old regex only knew `function policy(){}` and silently "compiled" other wrappers into a fn returning undefined; guarded by a zero-dep `bench/runner.test.mjs` (`npm test`, 12 cases). Compile-success jumped qwen 8% (11/144) -> 67% (6/9), codex 100%; remaining qwen fails are genuine model garbage (prose instead of code, repetition past the ceiling). Proof: `docs/screenshots/autoclaude-bench-fixed.png`. After the fix, a 1-hour loop gave the real, discriminating result: **codex 760** (score = XP/death avg of 3 seeds; it authored a genuine hunter policy that AVOIDS higher-level mobs via `levelDiff`, eats/retreats to survive, loots on a cooldown, runs an ability rotation off the GCD -> ~1151 XP at 0.7 deaths, 48 edits) >> random 22 (floor) > baseline 15 = qwen 15 (72 valid edits, none beat the seed). Takeaway: a frontier model dramatically self-improves given enough iterations; a 3B model writes runnable policies but plateaus at baseline. A short fixed-iteration sweep HID this (codex needs dozens of edits to break through), which is why the long loop matters. Proof screenshot committed at `docs/screenshots/autoclaude-bench-1hr.png`.
